Test mode

Keys that start with kt_test_ run everything on a simulator. Nothing uses minutes, no phone rings and no GPU is used, but permissions, spending limits, webhooks and errors behave like production. Use it to build and to run your tests.

#How to get a test key

In the app, open Developers and switch Production | Test to Test (the bar turns yellow). Keys created there start with kt_test_. Test data is kept apart: objects come back with &quot;livemode&quot;: false.

#What the simulator does

FeatureIn test mode
Rooms and meetingsCreated for real (with livemode: false), so you can open the links
AI agent in a roomWorks now. Two robot participants join: Kenji (speaks Japanese) and Lena (speaks French). They greet you and answer with fixed phrases, translated to your hear_lang
Phone callsWorks now with the magic numbers below
VoicesA cloned voice in test is a standard voice; nobody is contacted
WebhooksReal deliveries to your test endpoints, same signature
LimitsUp to 1,000 requests per day per test key (429 test_daily_limit)

#Magic phone numbers

NumberWhat happens
+1 555 0100Answers and replies with test phrases in English
+55 11 5555 0100Answers in Portuguese
+1 555 0101Busy
+1 555 0102Goes to voicemail
+1 555 0199Blocked destination (premium number)

Any other number is checked against the real rules (country, number type, purpose of the call) and then simulated.

quote a destination
curl "https://api.kanutus.com/v1/calls/quote?to=%2B15550100&purpose=scheduling" \
  -H "Authorization: Bearer $KANUTUS_TEST_KEY"

#Fire a test event

In Developers → Webhooks (Test), or with the API:

bash
curl -X POST https://api.kanutus.com/v1/webhook-endpoints/<endpoint_id>/test \
  -H "Authorization: Bearer $KANUTUS_TEST_KEY"

#Going live

Create a kt_live_ key in Production with the same permissions and swap it in. Agents in live rooms and live phone calls are Soon: with a live key those endpoints answer 501 not_available_yet today.
